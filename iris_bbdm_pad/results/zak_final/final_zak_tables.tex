\section*{Preamble: Evaluation Terminology}
% ═══════════════════════════════════════════════════════════════════════════════

\noindent
All four tables share the following notation.
\textbf{APCER} (Attack Presentation Classification Error Rate) is the fraction
of attack samples accepted as bona fide.
\textbf{BPCER} (Bona-fide Presentation Classification Error Rate) is the
fraction of bona fide samples rejected as attacks.
\textbf{ACER} $=(\text{APCER}+\text{BPCER})/2$;
\textbf{EER} is the Equal Error Rate (threshold-free).
All values are in \% and \emph{lower is better} for every metric.
$\tau$ is the classification threshold (score $\le\tau$ $\Rightarrow$ bonafide;
score $>\tau$ $\Rightarrow$ attack).
\textbf{Bold} marks the best ACER per attack row across compared models/steps.

  \textbf{Diffusion-based iris PAD comparison — Per-Attack Zero-Attack-Knowledge
  (ZAK-PerAtk) protocol.}
  %
  \textbf{Threshold rule:}
  For each attack type $a$, the threshold $\tau_a$ is the percentile $p_a$
  of bona-fide validation scores that minimises ACER on the per-attack
  validation subset $\mathcal{V}_{\mathrm{bon}} \cup \mathcal{V}_a$
  (bona fide $+$ that attack's val samples).
  The threshold \emph{value} $\tau_a$ is always drawn from the bona-fide
  score distribution (ZAK constraint on the threshold value).
  %
  \textbf{Why this is not purely unsupervised:}
  The \emph{choice} of percentile $p_a$ is made by evaluating ACER on
  $\mathcal{V}_a$, which contains labelled attack val samples.
  Specifically, APCER $= |\{x \in \mathcal{V}_a : s(x) \le \tau\}|/|\mathcal{V}_a|$
  requires knowing which val samples are attacks.
  The threshold \emph{value} is attack-free; the percentile \emph{selection}
  is not.
  This protocol is therefore semi-supervised in threshold calibration,
  distinguished from Table~2a where no attack information enters at any stage.
  %
  \textbf{Why BPCER varies across rows:}
  Each attack type receives its own $\tau_a$, changing the fraction of the
  fixed bona-fide pool rejected — so BPCER differs per row.
  Column $p$ shows the optimal percentile found for each attack.
  \textbf{Bold} = best ACER per attack.}

\section*{Zero-Attack-Knowledge (ZAK) Evaluation Protocol — Detailed Note}
% ═══════════════════════════════════════════════════════════════════════════════

\begin{tcolorbox}[
  colback=zakblue!60,
  colframe=blue!50!black,
  title={\textbf{ZAK Protocol Definition and Justification}},
  fonttitle=\small\bfseries,
  fontupper=\small
]

\textbf{Motivation.}
In operational iris PAD, the system designer has access to a large pool of
verified bona-fide enrolment images but has zero access to future attack
samples — the attacker's strategy is determined \emph{after} deployment.
A fully credible unsupervised PAD system must therefore set its
decision threshold without consulting any attack data.
The ZAK protocols formalise this constraint.

\medskip
\textbf{Common setup for both protocols.}
Let $\mathcal{V}_{\mathrm{bon}} = \{x_1,\ldots,x_{5276}\}$ be the set of
bona-fide validation images and $s(x) \in [0,1]$ the ViT-B/16 cosine
dissimilarity score produced by Diff-IrisPAD.
A sample is classified as a bona-fide if $s(x) \le \tau$, and as an attack
if $s(x) > \tau$.
Both protocols restrict all possible thresholds to the range
$[\min_x s(x),\,\max_x s(x)]$ for $x \in \mathcal{V}_{\mathrm{bon}}$
(thresholds \emph{outside} the bona-fide score range cannot be set).

\medskip
\textbf{Protocol A — ZAK-Global (Tables 2a, 3a): Purely unsupervised.}
\[
  \tau^{\mathrm{G}} = \mathrm{Percentile}_{90}\!\bigl(\{s(x):x\in\mathcal{V}_{\mathrm{bon}}\}\bigr)
\]
The 90th percentile is chosen as a \emph{design operating point}: it
guarantees that approximately 10\% of bona-fide validation samples score
above $\tau^{\mathrm{G}}$, i.e.\ BPCER$_{\mathrm{val}}\approx 10\%$.
This is analogous to setting a 90\% confidence level — a prior design
requirement stated before any test data is observed.
\textbf{No attack sample, label, or metric is consulted at any stage.}
Consequence: a single $\tau^{\mathrm{G}}$ is applied uniformly to all
attack types, so BPCER is \emph{identical} across all per-attack rows
within one model block (only APCER varies).

\medskip
\textbf{Protocol B — ZAK-PerAtk (Tables 2b, 3b): Semi-supervised calibration.}
\[
  p_a^* = \arg\min_{p \in \{1,\ldots,99\}}
    \mathrm{ACER}\!\bigl(\mathcal{V}_{\mathrm{bon}} \cup \mathcal{V}_a,\;
    \mathrm{Percentile}_p(\mathcal{V}_{\mathrm{bon}})\bigr),
  \qquad
  \tau_a = \mathrm{Percentile}_{p_a^*}\!\bigl(\mathcal{V}_{\mathrm{bon}}\bigr)
\]
where $\mathcal{V}_a$ is the set of validation images for attack type $a$.
\textbf{Why the threshold value is still attack-free:}
$\tau_a$ is always a percentile of the bona-fide validation scores —
it can only take values that lie within the bona-fide score distribution.
\textbf{Why this is nonetheless not purely unsupervised:}
Computing ACER to find $p_a^*$ requires knowing which $\mathcal{V}_a$
samples are attacks ($\mathrm{APCER} = |\{x \in \mathcal{V}_a : s(x)\le\tau\}|/|\mathcal{V}_a|$).
The percentile \emph{selection step} thus uses attack labels.
This makes Protocol~B semi-supervised in calibration:
attack-free in threshold values, attack-informed in percentile selection.
Consequence: each attack type gets a different $\tau_a$, so both APCER and
BPCER vary across rows.

\medskip
\textbf{Test pool construction (both protocols).}
To maximise attack coverage and remove any information advantage from the
original train/val/test split, \emph{all} attack images from both the
validation split (16{,}104 images) and the test split (34{,}508 images)
are merged into one evaluation pool (50{,}612 attacks).
Bona-fide evaluation uses only the 5{,}276 test-split bona-fide images;
the 5{,}276 val-split bona-fide images are reserved for threshold calibration
and are never counted as test samples.

\medskip
\textbf{Percentile grid.}
Both protocols sweep $p \in \{1, 2, \ldots, 99\}$ (99 candidate thresholds).
Protocol A fixes $p=90$ by design; Protocol B selects $p_a^*$ per attack
via the ACER minimisation above.
All percentiles are computed on $\mathcal{V}_{\mathrm{bon}}$ (5{,}276
bona-fide val images); the corresponding $\tau$ values depend only on the
bona-fide score distribution.

\medskip
